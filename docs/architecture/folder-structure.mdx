LASUMedScreen uses a feature-oriented folder structure designed around the Next.js 15 App Router. Every directory has a single, deliberate purpose — keeping concerns separated so you can navigate the codebase confidently whether you are adding a new screening field, wiring up a new Edge Function, or updating a shared UI component.

## Directory Reference

### `app/`

The `app/` directory is the heart of the Next.js 15 App Router. Route groups organise pages by access level without affecting the URL structure. The `(auth)` group contains publicly accessible pages such as login and registration, each with a lightweight layout that renders no navigation chrome. The `(dashboard)` group contains all protected pages — the student portal and the admin panel — wrapped in a shared layout that enforces authentication and provides the navigation sidebar. The root `layout.tsx` at `app/layout.tsx` mounts global providers such as the Supabase session context and the Toaster component.

### `components/`

Components are organised by domain, not by technical type. The `ui/` subdirectory holds base primitives generated by shadcn/ui — buttons, inputs, cards, badges, and dialogs. You should not edit these files directly; instead, compose them inside domain-specific components. The `forms/` directory contains form components built on React Hook Form. The `screening/` and `admin/` directories contain feature-specific components tied to their respective parts of the application. The `shared/` directory holds layout components such as the navigation bar, sidebar, and page header that are reused across multiple route groups.

### `lib/`

The `lib/` directory contains all utility code that supports the application layers. The `supabase/` subdirectory exports two distinct clients: `client.ts` creates a browser-safe Supabase client using the public anon key, and `server.ts` creates a server-side client that reads the session from cookies — suitable for use in Server Components, API routes, and Server Actions. The `middleware.ts` helper wraps session-refresh logic used by the root `middleware.ts`. The `validations/` directory contains Zod schemas shared between API routes and form components. The `email/` directory contains typed helper functions that wrap the Resend SDK.

<Warning>
  Never import utilities from `lib/supabase/server.ts` inside Client Components. The server client relies on Next.js cookie APIs that are unavailable in the browser. Use `lib/supabase/client.ts` for all client-side Supabase access.
</Warning>

### `supabase/`

The `supabase/` directory mirrors the structure expected by the Supabase CLI. Each subdirectory under `functions/` is a self-contained Deno TypeScript Edge Function. The `on-screening-submitted` function handles post-submission notifications, `send-clearance-email` fires when an admin approves a screening, and `notify-admin` delivers batched summary emails. The `migrations/` directory contains sequential SQL migration files managed by `supabase db push`.

<Warning>
  Never edit migration files manually after they have been applied to a database. Always generate new migrations with `supabase migration new <name>` and write your schema changes there.
</Warning>

### `types/`

The `types/` directory centralises all TypeScript interfaces and type aliases. The `database.types.ts` file is auto-generated by the Supabase CLI and reflects the exact shape of every table, view, and function in your Postgres database. The `screening.ts` and `user.ts` files contain hand-authored types and enums used throughout the application — for example, the `ScreeningStatus` union type and the `UserRole` enum.

<Warning>
  Always regenerate `types/database.types.ts` after schema changes with `supabase gen types typescript --project-id your-project-id > types/database.types.ts`. Editing this file manually will cause your types to drift out of sync with the database.
</Warning>

### `middleware.ts`

The root `middleware.ts` file runs on every incoming request before it reaches a page or API route. It calls the Supabase session refresh helper from `lib/supabase/middleware.ts`, validates the session token, and redirects unauthenticated users to `/login`. It also attaches the refreshed session to the response so that Server Components downstream receive a valid cookie without an extra round-trip.
