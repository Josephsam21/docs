LASUMedScreen reads configuration from a `.env.local` file at the project root during development, and from your hosting platform's environment variable UI in production. The app will fail to start if any required variable is missing or incorrect.

<Note>
  This page covers the minimum you need to get running locally. For the full variable reference, categorised tabs, and production guidance, see [Env Variables](/docs/configuration/environment-variables).
</Note>

## Create your `.env.local` file

Copy the example file and open it in your editor:

```bash Terminal
cp .env.example .env.local
```

Then fill in each value. At minimum you need the following six variables:

```bash .env.local
# Supabase (Settings → API in your Supabase dashboard)
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# Resend (resend.com → API Keys)
RESEND_API_KEY=re_your_api_key
RESEND_FROM_EMAIL=noreply@yourdomain.com

# App
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

## Where to find each value

- **Supabase URL and anon key**: Log in to [supabase.com](https://supabase.com), open your project, and go to **Settings → API**. Both values are listed under **Project API keys**.
- **Supabase service role key**: On the same **Settings → API** page, scroll down to **Service role key** and click the eye icon to reveal it.
- **Resend API key**: Log in to [resend.com](https://resend.com) and go to **API Keys → Create API Key**.
- **Resend from email**: Use any address on a domain you have verified in Resend. For development, `onboarding@resend.dev` works without domain setup.

<Warning>
  `SUPABASE_SERVICE_ROLE_KEY` bypasses Row Level Security and has full read/write access to your entire database. Never prefix it with `NEXT_PUBLIC_`, never log it, and never commit it to Git. Use it only in server-side code and Edge Functions.
</Warning>
